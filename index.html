Overview 00

About this project

Maintained by Rudra Khandelwal — B.Tech Computer Science & Engineering student. This guide is a personal working document for building and evaluating Hydra Launcher, the open-source game launcher, from source on Windows.

Agenda

build itGet a working development build from the official source using a clean, reproducible Windows toolchain.
vet itCheck dependencies, runtime behavior, network activity, processes, files and scanner results before treating the build as trusted.

AI-assistant scope

  • In scope: build troubleshooting, dependency auditing, configuration review and defensive process/network/filesystem checks.
  • Out of scope: cracking, brute-forcing or unauthorized access.
  • Secret handling: this public HTML contains no private credentials or vault data. Real secrets belong in a password manager or OS credential store.
  • Attribution: research entries identify [RUDRA], [CHATGPT], [CLAUDE] or [UPSTREAM] where relevant.

The terminal approach — how & why 08

step 1
Open Developer Command Prompt for VS 2022.

step 3
Force VS2022/v143:

Security check workflow 12

The goal is measurement and documentation, not a predetermined conclusion.

sourceRepository, commits, dependencies and scripts.
buildUnexpected downloads, scripts, warnings and failures.
networkDomains, IPs, ports, timing and owning process.
processesChild processes, paths, command lines and persistence.
filesNew executables, DLLs, scripts and unexpected files.
scansDefender, VirusTotal and exact hashes/results.
Research rule: a warning or unknown connection is something to investigate, not automatic proof of malware.

Exact documented point reached in the current Hydra security investigation. No third-party game download or execution has been performed.

Confirmed evidence

  • Process, network and filesystem snapshots were created under security-research before any game-download test.
  • Hydra Electron HTTPS connections were observed during runtime and owning processes were recorded.
  • Adding a source sends its URL to Hydra's /download-sources API; profile sync is separate.
  • DownloadSource.url is the registry/source URL while DownloadSourceDownload.uris contains actual download URIs.
  • Hydra recognizes specific host prefixes plus magnet:; arbitrary HTTPS is not automatically treated as a downloader.
  • HTTP and torrent downloads split into JsHttpDownloader and the native libtorrent path.
  • The internal Downloader.Hydra branch throws NotCachedOnHydra rather than directly executing an arbitrary URI.
  • hydralinks.cloud/sources/fitgirl.json is an unverified third-party/community source. A direct request returned HTTP 403 during testing; that is an anti-bot response, not proof of malware.
Next: trace TorrentService and executeDownload() deeper, then inspect extraction and launch handling before any controlled third-party download test.

Troubleshooting 14

spawn cargo ENOENT

Rust is unavailable to the current terminal.

where cargo
where rustc

CMake says Visual Studio 18

Force VS2022/v143:

set CMAKE_GENERATOR=Visual Studio 17 2022
set CMAKE_GENERATOR_PLATFORM=x64
set VCPKG_VISUAL_STUDIO_PATH=C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools
set VCPKG_PLATFORM_TOOLSET=v143

__std_* unresolved linker errors

Likely mixed MSVC toolsets; run where cl and confirm VS2022.

undefined.includes("staging")

Verify the two required API/auth variables in .env and restart yarn dev.

Sign-in window / DevTools disconnect

Verify MAIN_VITE_AUTH_URL=https://auth.hydralauncher.gg, then restart development mode.

No downloads available

Catalogue and download sources are separate from the compiler/build process; third-party sources remain independent trust decisions.

Vite dynamic-import warnings

These can be bundling warnings rather than fatal build failures.

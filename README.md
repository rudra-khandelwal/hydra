## Why this repository exists

This repository is Rudra Khandelwal's public workspace for building, understanding, documenting, and security-testing a local copy of the open-source Hydra Launcher project.

The work is intentionally separated from the upstream project so that local experiments, research notes, test evidence, build configuration, and security findings can be developed without presenting them as official Hydra project statements.

## What we are doing

We are studying the application through:

- source-code inspection
- reproducible Windows builds
- dependency and build-environment analysis
- process observation
- network observation
- filesystem observation
- controlled installation/execution tests
- file hashing and malware/AV checks
- documentation of third-party integrations
- chronological research notes and evidence

The research goal is **measurement and documentation**, not a predetermined conclusion about whether the software is safe or unsafe.

The 25 September 2026 checkpoint records API-mediated download-source metadata, client-side source synchronization, and the antivirus/AMSI control result. No malware verdict has been established, and no third-party game/software executable has been downloaded or executed as part of this checkpoint.

## Important trust boundaries

The research treats these as separate components:

1. Hydra application/source code
2. Hydra API/authentication services
3. configured community/download sources
4. third-party download infrastructure
5. downloaded installers or game/software files
6. software executed after installation

Evidence about one boundary is not automatically evidence about another.

## Research method

Every substantive research checkpoint follows:

**Fact → Observation → Hypothesis → Finding → Next Action**

Findings should identify their evidence and uncertainty. Hypotheses are not recorded as facts.

## Public repository safety

Because this repository is public, every committed file and its Git history should be treated as public.

Do not commit:

- passwords
- access tokens
- API keys
- cookies
- private keys
- recovery codes
- personal authentication data
- raw logs containing credentials or personal data
- downloaded proprietary/copyrighted game or software files
- generated build artifacts unless intentionally documented

Use `.env.example` for configuration templates and keep real `.env` files local.
